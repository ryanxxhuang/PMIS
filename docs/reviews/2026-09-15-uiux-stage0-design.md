## 0. 給決策者的一頁摘要

1. **仍成立且可直接修的**：驗收未選結果預設合格（U01）、送審／疑義新增失敗會收表單並清輸入（U02、U03）、AI 讀文件「可離開稍後回來查看」與實際不符（U14 推定）、RFI 廠商提示描述不存在的「追問」（U10 推定）、頂欄 AI 入口可及性名稱以「搜尋」開頭（U11）。
2. **入口結構的真問題只有一個**：桌機側欄子頁與頁內分頁 `PageTabs` 在 1280px 以上同時出現，與 D-015「內容區不重複子頁導覽」衝突；但在 768–1279px 平板與 375px 手機，`PageTabs` 是唯一看得到的子頁導覽。推薦 **方案 C（依尺寸互補）**，見 §3.2。
3. **未匯標單時首頁把待辦整個藏起來**（U05）：`Dashboard.jsx:222` 只渲染初始化清單；送審、疑義、契約期限、驗收、工安都不依賴標單卻看不到。初始化清單也對非管理員顯示（U12）。
4. **建議先做的包**：包 1「操作可信度」（＝提示的階段 1），不依賴任何入口決策；包 2a「首頁待辦與初始化並存」也不依賴入口決策；包 2b「入口方案」等你決定 §3.2 後再做。
5. **需你決定的產品邊界**共 7 題，見 §5.1；其餘為可直接做的前端改善，見 §5.2。

## 2. 三角色主要任務：目前 → 建議

標記：**【中斷】**流程在此停下要另起一步；**【重找】**要重新找到剛才那一筆；**【資料不足】**畫面沒給下一步需要的資訊。頁面與動作名皆為現有字串。

### 廠商 C1：寫今天的施工日誌（含照片）

目前：首頁待辦「今天的施工日誌尚未填寫」或底欄「日誌」→ `/site-log`（日期預設今天）→ 帶入天氣／複製昨日 → 填工項數量、公定欄位 → 貼底列「存檔」→「已存檔 ✓」→ 照片卡「上傳」**【中斷】**未存檔前上傳會被擋（「請先存檔本日日誌,才能上傳照片」）→ AI 辨識覆核 → 再「存檔」。頁上另有「AI 拍照自動填寫」（告示板）與照片卡批次辨識兩套 AI 入口**【資料不足】**：兩者差異只在小字。從待辦進來可「返回今日待辦」，直接進頁則無回程。

建議：流程不動。①存檔成功後在貼底列顯示「已存檔 ✓ 14:32」並保留 3 秒 snackbar，與送審／疑義用同一種回饋（§5.2）。②照片卡在未存檔時把「上傳」換成「先存檔本日日誌」按鈕，就地觸發 `onSave`（不新增資料流）。③兩個 AI 入口併成照片卡內的一組（候選，非階段 1）。

### 廠商 C2：提送送審，退回後補正再送

目前：首頁「送審」常用鍵或底欄 → `/submittals` → 頁首「提送送審」→ 清單上方表單卡 → 「提送」→ 表單消失、**沒有回饋**、清單選取仍是開頁時自動選的那一筆**【重找】**新紀錄在清單最上方但未被選中 → 點它 → 詳情「上傳文件」才能附文件本體**【中斷】**提送與附件是兩步。失敗時（RLS、網路）表單同樣消失**【資料不足】**使用者以為成功。退回補正：待辦「送審」→ `?submittal=` 直達 → 「修正再送」對話框填補正說明 → 完成，同樣無回饋。

建議：①「提送」成功後 `select(newId, { openPane: true })` 並 snackbar「已提送 SUB-012，可在詳情上傳文件本體」；失敗時表單保留、`ErrorBanner` 貼在表單上方、按鈕可重試。②表單卡加一行「文件本體可在提送後於詳情上傳」，消除「要先準備附件」的猶豫。③（候選）表單改成詳情欄／手機 sheet 內的「新送審」，讓提送與上傳在同一位置。

### 監造 S1：查驗判定

目前：首頁待辦「查驗」→ `/quality?inspection=` 直達抽屜／詳情 → 「合格」或「不合格」（原因對話框）→ 「返回今日待辦」。已由 PR #83 補齊。剩餘摩擦：`/quality` 本身是路由器：「現在要處理」佇列＋查驗／觀察／試體三段＋頁首「現場與品質」分頁列，一頁三層切換**【資料不足】**第一次進頁不知道該看哪一層。

建議：不動流程；把「現在要處理」佇列標為主清單、三段標題改為快篩 chip 語彙（候選）。判定成功回饋沿用 snackbar。

### 監造 S2：審定送審（含 AI 讀文件）

目前：待辦「送審」→ `?submittal=` → 詳情 → 「受理審核」（意見可留空的對話框）→ 狀態變審核中 → 「AI 讀文件審查」→ 橫幅「約需 20–30 秒,可離開此頁稍後回來查看」**【資料不足】**離頁結果就消失（U14）→ 「核准」對話框帶入草稿 → 完成無回饋；那一筆離開「待我處理」快篩但詳情仍顯示（正確）。

### 機關 O1：核定變更設計

目前：首頁「變更」常用鍵 → `/change-orders`（未匯標單即整頁 Empty）→ 清單預設選第一筆待核定 → 寬版詳情：狀態＋淨額、明細表、動作列 → 「核准」**直接寫入，沒有確認框**（`ChangeOrderDetail.jsx:272`），核准後明細凍結，撤銷為機關專屬（D-016）→ 無回饋，只換狀態章。頁首四張 Stat 在手機收成三格條。

### 機關 O2：登錄付款

目前：待辦「估驗」（機關責任期限）→ `/payments?period=N` → 該期列聚焦（找不到期別時「顯示全部期別」）→ 填收款日／實收金額，`onBlur` 寫入 → 無成功回饋**【資料不足】**只有失敗才有紅字；手機為唯讀摘要（設計決定）。頁名「請款收款」對機關是付款。

### 3.2 方案對比與 D-015 衝突

D-015 原文：「桌面側欄可收合、子頁可展開／收合，手機同一階層，內容區不重複子頁導覽。」現況：`ui.jsx:100` 讓每個 `PageHeader` 都長出 `PageTabs`，所以 1280px 以上展開側欄並展開群組時，同一組子頁在側欄與內容區各出現一次，違反最後一句；但 768–1279px 的 rail 不顯示子頁（`Layout.jsx:337` 平板一律 rail，展開鈕 `md:hidden`），`PageTabs` 反而是唯一子頁導覽，直接移除會讓平板只能靠尋找功能或抽屜換子頁。

| 方案 | 內容 | 優點 | 代價 |
|---|---|---|---|
| A 保留 PageTabs（現況） | 側欄可展開＋每頁都有分頁列 | 零改動；平板、手機子頁可達 | 1280＋ 重複導覽，與 D-015 衝突；頁首多一列，`Progress.jsx:358` 已因分頁列擠壓動作鈕 |
| B 減少重複：PageTabs 全尺寸退場 | 側欄群組依路由自動展開；平板 rail 加「子頁飛出選單」；手機靠抽屜與底欄 | 導覽只有一份 | 需新做 rail 飛出層（新元件、新 e2e）；手機從「施工日誌」切到「品質查驗」要開抽屜（多一步） |
| **C 依尺寸互補（推薦）** | 側欄展開時：目前群組自動展開，`PageTabs` 不渲染；側欄收合／rail／手機：`PageTabs` 渲染 | 每個尺寸都只有一份子頁導覽；不新增元件；平板與手機零變化 | `PageTabs` 需讀側欄狀態（可從 `Layout` 以 context 或 `data-` 屬性提供）；D-015 需補一句「子頁導覽依尺寸擇一顯示」 |

### 4.1 送審詳情（監造視角，1440 兩欄／375 推入抽屜）

### 4.2 廠商施工日誌（375 為主、1440 為輔）

375：頁首 → 日期／上午天氣／下午天氣兩欄 → 工作摘要 → 工項數量（搜尋加列，每列數量欄右對齊）→ 公定欄位（預設展開，可收）→ 照片卡（未存檔時顯示「先存檔本日日誌」就地按鈕）→ 貼底存檔列（「存檔」＋「已存檔 ✓ 14:32」）。1440：同一流程單欄，最大寬 880px，不套清單／詳情殼（規範 §8 明訂）。主要動作只有「存檔」；AI 辨識為次級，結果以「AI 草稿」前綴標示。

### 4.3 機關變更設計（1440 寬版兩欄／375 唯讀摘要）

1440：Stat 四格（原契約、追加、減帳、變更後金額）→ 左欄清單（待核定在前，列尾淨額）→ 右欄 640px 寬版詳情：狀態章＋淨額 → `MetaGrid` 四格 → 追加／減帳明細表 → 動作列「核准」（實心）／「駁回」（danger）／等待字樣。核准前確認框列出淨額與變更後契約金額。375：Stat 收三格條；清單→推入抽屜；明細表橫向捲動；核定鈕依 §9.6 精神在手機不渲染，顯示「核定請在桌面進行」（待你確認，§5.1 D5）。
