# PMIS UIUX：交給 Claude Code 的分階段 prompts

> CANDIDATE｜2026-09-15｜這是可複製的任務提示，不是要求自動執行整份文件。
> 搭配 [診斷報告](/Volumes/GameSSD/Projects/PMIS/docs/reviews/2026-09-15-uiux-diagnosis.md)。

## 使用方式

在 PMIS 專案開啟 Claude Code，**一次貼一個階段的程式碼區塊**。每段都會要求它讀共通規則，無須一次貼整份報告。

想先看方向：貼階段 0。想先處理最明確的問題：貼階段 1。階段 2 要先有入口配置決定；後續依 3A → 3B → 3C → 4 → 5A → 5B → 5C → 6 進行，可以按業務優先順序調整互不相依的項目。

每次看完改前／改後、失敗情境與驗證結果，再指定下一包。不要用「照這份報告全部做完」作為總提示。

## 共通規則（每個階段都必須遵守）

1. 先讀 AGENTS.md、DEVELOPMENT.md、CURRENT.md、docs/DECISIONS.md、docs/UIUX-Apple-設計規範.md，以及本次對應的架構文件與診斷問題。先查工作樹，保留他人變更。
2. 報告基準是 `7156aeff2ef21789f422fdab4739426072849cec`，包含 PR #83。先確認最新程式是否仍有問題；已解決就記錄，不重做。報告是證據與候選方向，不是凌駕程式和既有決策的新規格。
3. 本次使用者只授權貼上的那個階段／子階段。未指定階段不實作；只閱讀本檔其他提示不構成授權。
4. 工作重心是使用者任務。實作前在工作紀錄寫五行「問題、目標、不做、影響、驗收（最多五項）」。先說明改前／改後的操作順序，再在授權範圍直接完成，不只交一份建議。
5. 角色維持 contractor／supervisor／owner。現場、品管、工安不是新角色。監造核定估驗；機關核定變更。不得改 RLS、RPC、Guard Trigger、金額／期限／品質判定公式、契約來源權威或 AI 人工決策邊界。
6. 沿用既有路由、navConfig、設計 token、共用表單、listDetail 與確認對話框。不要換 UI 框架、另建工作流程引擎、一次重寫全站或無第二使用點就抽象化。
7. 對草稿、新狀態、手機辦公室表格開放編輯、背景 AI 持久化、多欄原子金流寫入等產品邊界，先列具體方案與代價，由使用者另行決定。完成不受影響的已授權工作；不能以方便前端為由偷偷改後端。
8. 不讀取／修改正式業務資料來製造展示，不把 Demo 通過當成正式環境已驗收。可用的本機測試與失敗模擬應直接完成；工具或帳號受限時如實列出未驗項，不繞過限制。
9. 實作階段跑 DEVELOPMENT 指定的文件檢查、lint、單元測試、build，及影響範圍的 E2E。優先驗證使用者任務、錯誤／取消／返回與角色限制，不為純視覺小改寫一堆鏡像測試。未改 DB 不新增無關 migration。
10. 實作後同步 CURRENT、受影響架構／操作說明及 BASELINE，只記已實作／已驗證範圍；候選留在提案。純分析階段不要把建議寫成現況。
11. **這組提示預設只交付本機可檢視的修改。不要 commit、push、建立或合併 PR、部署、執行正式 migration。** 這是本次提示的明確範圍，優先於 D-023 常設授權；使用者之後要求發布時再處理。
12. 完成回報包含：改善了哪個操作、改前／改後、涉及頁面、實測結果、仍有限制；能取得畫面就附桌機網頁版證據。不得把「測試通過」寫成「真人覺得直覺」。
13. **模型分工：簡單且低風險的工作使用 opus5；複雜或高風險的工作使用 fable5.1。** 單純文案、間距、樣式及局部呈現調整可用 opus5；跨頁流程、狀態保存、錯誤恢復、核定／驗收／金流操作及共用元件行為變更使用 fable5.1。開始每個工作包前先判斷複雜度與風險；同一階段可依子任務分配，若難以判斷則使用 fable5.1。模型選擇不擴大本次授權範圍；若環境無法切換或找不到指定模型，明確告知，不宣稱已切換。

14. **為減少工程量，本輪只針對產品的桌機網頁版，涵蓋機關、廠商、監造三角色；手機、平板及其他裝置的專屬 UIUX、響應式版面、觸控與跨裝置流程之後再處理。** 各階段的設計、實作、畫面交付與新增驗收均以桌機瀏覽器為準，不另做手機／平板版本，也不以其尚未優化阻擋本輪完成。保留既有響應式與裝置權限界線；共用修改造成的直接回歸仍須修復，但不藉此擴大為行動版改造。既有必要回歸測試照常執行，不刪除或跳過測試來通過驗收。其他文件或舊草圖若要求三尺寸／手機／平板專屬工作，以本條最新範圍為準，記為延後。

## 階段 1：修正使用者對操作結果的誤判

```text
請實作 PMIS UIUX 階段 1：操作可信度，只處理 U01、U02、U03 的近期文案方案及 U13 的錯誤提示文案。

先讀 docs/reviews/2026-09-15-claude-uiux-prompts.md 的共通規則與診斷報告。先核對問題是否仍存在，再完成本階段；不做導航改版。

範圍：
- Acceptance.jsx：需要結果的階段，使用者未明選合格／不合格時不可送出。空值不得預設合格；就近提示並能聚焦修正。保存失敗保留輸入；不改既有期限、狀態與角色。
- Submittals.jsx、RFI.jsx：檢查建立函式回傳錯誤；失敗不收起表單、不清掉圖面與輸入，顯示可重試錯誤；成功才收起並定位新增項。處理預期錯誤及非預期例外的 busy 收尾，防止重複點擊。
- 送審 AI 讀文件：核對離頁／重進是否可恢復結果；若沒有，修正「可離開稍後回來查看」的承諾，清楚說明現有保存範圍，不實作背景工作。
- 核對角色提示：不描述不存在的同筆 RFI 追問；保留驗收的專案脈絡及契約原文優先等重要資訊，不新增業務動作。

最多五項驗收：
1. 驗收未選結果不發寫入；合格／不合格各依明選結果送出。
2. 新送審與新疑義失敗保留全部輸入，重試成功可找到新紀錄。
3. 取消、失敗、成功的回饋不同；送出中不能重複送；未知寫入結果不假稱一定失敗或已完成。
4. AI 離頁文案與實際可恢復能力一致，沒有新增資料持久化或第二套 AI 入口。
5. 三方權限、核定順序、公式與正式資料未改變。

請補能重現失敗與未選結果的測試，完成規定驗證與現況文件更新，交付本機 diff。不要執行後續階段或發布。
```
