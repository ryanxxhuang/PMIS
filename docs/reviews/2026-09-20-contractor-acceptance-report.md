## 結論

**尚未達到「照片上傳後，AI 填好真實表單，工程師審核簽署即可送出」的交付標準。** 已有文件版本、簽署、收件及確認量計價的基礎，不需要重做整個系統；優先補角色介面、照片資料模型、紙本直接編輯與 PDF 交付。

可用來展示既有流程；在以下阻擋項通過前，不建議以「全部文書自動完成」交付廠商正式使用。

### 已完成的真實 Anthropic 基準測試

使用者已授權這五張照片傳至 Anthropic，並要求將新金鑰寫入本機 `.env.e2e.real`；已完成，金鑰未寫入報告或 Git。前次 401 是舊金鑰，本次已恢復正常，不再是驗收阻擋。

本次直接使用 `f99bfee` 既有 `sitePhotoCall`／`claudeJson`，對原始 JPG 做分類；依現行 `has_board` 條件再呼叫 `whiteboardCall`。**5 張分類＋3 張轉錄，共 8 次 API 呼叫全數成功**；模型為 `claude-haiku-4-5-20251001`，usage 合計 input 39,561／output 1,656 tokens。未修改 prompt、模型或產品程式。沒有使用 stub，也沒有走完整網頁上傳、標單配對、存檔、簽署或計價流程。

完整模型回應、來源檔 SHA-256、prompt 檔 SHA-256 與版本見 [真實辨識基準 JSON](assets/2026-09-20-contractor-acceptance/vision-baseline.json)，不含金鑰或影像原檔。

| 照片 | 現行模型實際輸出 | 驗收判斷 |
|---|---|---|
| `LI2995~1_0.JPG` | 分類為查驗會勘；caption 寫「#5、#4」「梯號U-36」「梯級 D20@20cm」等；visible_progress 寫「鋼筋綁紮完成」；轉錄只取得日期，其他文字空白、items=[] | 出現錯讀與無法由照片判定的完成狀態；未取得右側已填的實測尺寸 |
| `LI89DE~1_0.JPG` | 正確辨識游標卡尺量測鋼筋，沒有猜讀值；工項只回「鋼筋」 | 場景描述可用，但過泛工項仍需本案標單配對；不能當實測填表完成 |
| `LIEE66~1_0.JPG` | 有辨識卡尺量測且未猜數字，但 caption 額外聲稱「木樁樁頂面可見」 | 沒有足夠影像證據支持木樁判斷，應移除或標不確定 |
| `LIFA1C~1_0.JPG` | caption／visible_progress 寫「D13、D16、D29」「間距13、15 CM」；轉錄只取得日期 | 將線徑、編號與間距混讀，缺少實測欄 11×11 mm、15×15 cm 的結構化紀錄 |
| `LINE_A~4_0.JPG` | caption 出現「訊光建設」「樓層11F」「2層密集配置」及「綁紮完成」；結構化 location="11F"，但轉錄 location="" | 憑空產生公司／樓層等資訊；**錯誤位置已進入結構化欄位**，可能污染後續草稿分組，優先阻擋 |

此樣本內：5/5 分類為查驗會勘、3/3 紙表有觸發轉錄、3/3 日期為 2026-08-04；但三張紙表的說明均有錯讀／無來源內容，且三張都未產出可對應實測尺寸的結構化資料。**本輪照片填表品質不通過。** 這只是五張、單次呼叫的回歸基準，不是一般辨識準確率。

重要修正方向：本次不是「紙表完全未觸發辨識」；現行模型有回 `has_board=true`。核心問題是分類 caption 猜測，以及轉錄 schema 無法承載設計／實測欄與尺寸。三張 `items=[]` 本身不代表錯誤，因為紙上沒有寫當日完成數量；**不可為了填滿 items 而把尺寸變施工量**。應另建實測觀察欄位、來源定位與單位檢核，才能帶入草稿。圖中不清楚的精密讀值仍應留空。

尚未做改善後對照；沒有聲稱已優化。Claude 修改後須沿用此基準比較，不能只以 API 成功、日期正確或一段 caption 代表整張表自動填好。`e2e-real/chain5-field-docs.spec.js` 的本機 vision stub 仍只證明流程。

## 契約與估驗：保留基礎，補足整合驗收

確認量來源分配、截止日、已計價與占用量、簽署版本、退回及更正已有 migration、UI 與測試實作。本輪未重跑真 DB／真後端整條簽核鏈，不能替正式部署背書。Claude 要以真後端測完「自檢→申請查驗→監造確認→草稿估驗自動更新→送審」及拒絕繞過的案例。

兩項既有產品限制須向廠商明示，不宜偷偷變更：

- 總價／間接費依 D-026 暫時 `cap=0`。若試用專案需要這類請款，這就是該專案完整請款的阻擋項；不能以隨意的合格查驗解鎖。
- 掃描／無文字契約目前不採付費 OCR。需能清楚顯示無法抽取、人工補登及缺少基準日；不能承諾所有契約都可自動追期程。
