## 二、修補歷程（漏洞修復有效性之佐證）

附表十構面七要求「漏洞修復應**測試有效性及潛在影響**」。本案的修補與複測紀錄：

| | 第一次掃描（搬遷前） | 第二次掃描（修補後） |
|---|---|---|
| 標的 | `ryanxxhuang.github.io/PMIS`（GitHub Pages） | `gov-agent.ai`（Cloudflare Workers） |
| High | 0 | **0** |
| 警告類別 | 13 | **7** |
| 通過檢測項 | 54 | **60** |

**修補內容**：第一次掃描的 13 類警告中，**7 類根因相同**——GitHub Pages 不支援自訂
HTTP 回應標頭，導致 CSP、X-Frame-Options、X-Content-Type-Options、Permissions-Policy
等無法設定。已將服務移轉至支援自訂標頭的主機，並以 `public/_headers` 統一設定，
**複測確認該 7 類全部消失**。

搬遷前的報告一併保留於同目錄（`*-搬遷前githubpages.*`）作為修補歷程佐證。

> 皆為「無要求」**，故安全標頭**本身不是條文要求**，而是「測試階段應執行弱點掃描」
> 掃出的結果要求的。本公司選擇一併修正而非敘明不適用。

## 三、剩餘 7 類逐項處置

### A. 刻意的設計決定（3 類）

| ZAP 規則 | 內容 | 為什麼維持現狀 |
|---|---|---|
| **90004** COEP 未設定 ×8 | 未設 `Cross-Origin-Embedder-Policy` | **刻意不設。** COEP（`require-corp`）會擋掉未帶 CORP 標頭的跨來源資源，本服務的中文字型（Google Fonts Noto Sans TC）會因此無法載入。COEP 的實際用途是解鎖 `SharedArrayBuffer`，本服務未使用。已設 `Cross-Origin-Opener-Policy: same-origin` |
| **10055** CSP `style-src unsafe-inline` ×3 | CSP 允許行內樣式 | React 的 `style={{...}}` 會產生行內樣式屬性，移除等同重寫全部元件的樣式寫法。**風險已由更嚴格的 `script-src 'self'` 抵銷**——本服務無任何行內 script、無第三方 CDN，XSS 的主要途徑已封閉 |
| **10015／10049** 快取相關 ×10 | 靜態內容可被快取 | **刻意設定**：內容雜湊過的 `/assets/*` 設 `max-age=31536000, immutable`（檔名含雜湊，內容變更即換檔名）；入口頁 `index.html` 設不快取。所有需登入的資料一律不經此路徑 |

### B. 誤報或不適用（2 類）

| ZAP 規則 | 內容 | 理由 |
|---|---|---|
| **10096** Timestamp Disclosure ×5 | JS 中出現類 Unix timestamp 的數字 | **誤報。** 命中的是 demo 資料檔（`workItems.compact`）中的工程數量與金額常數，非系統時間戳，無資訊洩漏 |
| **90003** SRI 未設定 ×3 | script／link 未帶 `integrity` | **不適用。** 本服務**所有 JavaScript 均為同源自載，無任何第三方 CDN**（Vite 產出之檔名含內容雜湊，已具內容定址效果）。唯一的跨來源資源是 Google Fonts 樣式表，而 Google 會依瀏覽器回傳不同的 CSS，固定雜湊反而會導致字型永久失效 |

### C. 資訊性提示（1 類）

| ZAP 規則 | 內容 | 說明 |
|---|---|---|
| **10109** Modern Web Application ×3 | 「這是一個現代 SPA」 | ZAP 的資訊性標記，用於提示掃描器本身，**非弱點** |
